KVQuery versus Tessil robin-map — extended offline comparison

Robin-map: 91362aab8f2c63ef90bf7c21fb2c3283ded5ae48 (v1.4.1-2-g91362aa). Upstream: https://github.com/Tessil/robin-map
Host: Core Ultra 9 285K, 24 cores, approximately 64 GB RAM; all measured lookups use logical CPU 10, a performance core. Windows 11/Cygwin, GCC 14.4.0.
No measurement runner/harness network requests. The only dependency acquisition was the initial robin-map clone; the exact upstream source archive is retained.

Protocol: 3 independent processes per workload, 5 methods per process. Each heavy-workload method runs for at least 30 seconds; cache and single-key diagnostic methods run for at least 10 seconds. Nominal timed lookup work: 1,200 seconds (20 minutes). Actual measured wall time is recorded, including pauses.
One timed interval per method per process. Workload order reverses on the middle repeat; method order rotates/reverses deterministically by seed. All methods share identical records and query traces within a process. Queries are a cyclic 1,048,576-key uniform trace with a 90% hit target.

Result semantics: input-ordered optional string views; no payload copies. The robin-map and std::unordered_map fixtures stay alive throughout the process. Native KVQuery batches retain snapshot ownership. Timing includes result allocation/destruction, lookup, KVQuery owner handling, and value length/endpoint-byte consumption. Full result bytes are checked across the entire trace outside timing; completed timed batches are checked against independently generated expected checksums. Since timed methods complete different numbers of batches, their final checksum totals need not equal each other.
Same initial 64-bit mixer and requested maximum map load factor 0.8. Actual load factors and capacities differ because growth policies differ; they are recorded. All comparison code uses the same compiler/optimization/ISA tuning. The harness uses -std=c++20; the separately built KVQuery library uses -std=gnu++20 with the same -O3 -DNDEBUG -msse4.1 -mtune=native settings. Full original flags and commands are retained.

PROJECT SCOPE
KVQuery is an immutable uint64-to-bytes snapshot engine with batch scheduling, compact nodes, small-value inlining, snapshot-owned result lifetimes and checked snapshot persistence.
Tessil robin-map is a generic mutable C++ Robin Hood hash-map/set library. Its const find interface is adapted to ordered batch views here; insertion/erasure and serializer/deserializer hooks are broader features outside this read-only timing. Upstream source and MIT license are preserved. KVQuery licensing and source provenance are preserved separately.
This is a complete storage/API/read-path comparison, not an isolated measurement of SIMD, hashing, or memory footprint. Different table representations and capacity rounding are part of the tested configurations.

LIMITS
These are synthetic single-thread read-only lookups on one shared desktop. The run is not a concurrent-service, network-QPS, open-loop queueing, update-throughput or persistence benchmark. The single-key SIMD path uses a direct comparison; it is not a vector-comparison speedup test. Three process repetitions support min/median/max descriptions, not strong significance claims for small differences.
Performance conclusions must be tied to each workload. All measured methods, slower results, long intervals and unselected smoke/pilot artifacts are preserved. The SQLite pilot uses owned copies and a different protocol; it is excluded from every selected-comparison table.

REPRODUCTION AND FILES
manifest.json: exact revisions, commands, build flags, seeds, host, capacities and source/binary SHA-256.
runs/: raw per-process JSON, console logs, every sampled batch latency, and every retained interval throughput row.
summary.csv and per-process-summary.csv: tabular summaries. throughput-timeseries.csv: all monitor intervals. validation.json: checksum/sample/percentile/accounting checks.
source/: exact source archives, benchmark harness, runner, original library flags, original project license/NOTICE and upstream MIT license. compiled-inputs.zip preserves exact measured source bytes/line endings. bin/: measured executable and library.
The benchmark executable pins CPU 10 and requires the recorded Cygwin runtime and SSE4.1-capable hardware. On another host, inspect allowed CPU topology and update the pin explicitly. Original Cygwin/runtime dependencies are in toolchain-runtime.txt.
To rebuild from extracted source archives, compile KVQuery src/kvquery.cpp with its retained GNU C++20 library flags, then compile the retained harness with the manifest command and the pinned robin-map include directory. The saved runner documents all 12 process commands and their order.
SHA256SUMS.json hashes all retained files before this bundle was packaged. The final ZIP contains the complete expanded results directory.
