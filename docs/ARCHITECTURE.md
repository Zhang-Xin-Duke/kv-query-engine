# 设计与实现

[项目首页](../README.md) · [API](API.md) · [性能评测](BENCHMARKS.md)

## 1. 组件边界与数据流

引擎处理一组 `uint64_t → bytes` 记录。构建器把记录整理成紧凑哈希索引和连续 Value 区域；查询器根据 Key 找到对应字节，按输入顺序返回视图；文件接口负责保存记录以及校验加载。

```text
Record[] → 参数与长度检查 → Value 区域 + 元信息 → NeighborIndex → Snapshot
文件     → 文件头与记录解析 → 校验和检查       → 同一构建路径    → Snapshot
Key[]    → 策略执行器      → 输入位置回填     → BatchResult（持有 Snapshot）
```

快照发布后，索引和数据保持不变。查询所需的状态、输入位置和结果数组均属于当前调用，所以多个线程可以直接共享同一份快照。一次批量查询始终从该快照读取。

采用快照是为了把构建工作与读取分开：读取获得稳定地址，构建器可以在另一份数据上处理冲突和分配内存。更新由调用方创建新快照并安排请求切换，新旧数据的共存时间由结果句柄的生命周期决定。当前组件提供快照对象，应用负责版本调度、服务入口和记录编码。

## 2. 内存表示

### 索引节点

`detail::NeighborIndex::FlatNode` 是连续数组中的 16 字节节点，使用编译期 `static_assert` 检查大小。

```text
+---------------------------+  64 bit
| key                       |
+---------------------------+  64 bit
| chain:10 | length:18 | offset:36 |
+---------------------------+
```

| 字段 | 表示 | 使用方式 |
|---|---|---|
| Key | `uint64_t` | 比较完整 Key |
| Offset | 低 36 位 | 定位自有 Value 区域 |
| Length | 接下来的 18 位 | 普通长度或 `262143` 扩展标记 |
| Chain | 高 10 位 | 解码为 −512 到 +511 的相对槽位偏移；零表示链尾 |

将链位置放入节点，省去一个独立指针字段。相对位置的范围限制了节点放置，构建时需要寻找能与前后端点连接的空位。这个选择把放置与修链工作留在构建阶段，读取只需检查节点并沿相对链跳转。

### Value 区域

Value 字节保存在独立的连续数组中。固定大小的索引节点因此能够指向不同长度的文本、序列化结构或向量数据。查询索引不必读取完整 Value。

第零个字节保留，使每条有效记录的位置至少为 1。节点的打包字段全为零表示空槽，Key 为零和零长度 Value 也能被正常存储。多个空 Value 可以指向同一末端位置，因为它们的有效长度均为零。

长度小于 `262143` 时直接编码。达到该值后，将真实长度作为小端 `uint32_t` 放在 Value 前四字节，节点保存扩展标记与正文位置。读取扩展值时，先解码前缀，再生成视图。

### 定位与循环下标

桶定位先对 `key XOR seed` 执行 64 位混合，再使用 128 位乘法的高位将结果映射到桶数范围。普通循环跳转通过一次加减完成；很小的表在邻域搜索中可能绕回多次，此时使用完整取模修正。

链编码使用无符号移位，并显式解码符号位。这样，表示和跳转的行为可以通过边界测试直接验证。

## 3. 索引构建

### 准备数据

`Snapshot::build()` 先校验负载因子、记录数和索引预算，再累计 Value 所需空间。长度和总量检查完成后，预留 Value 区域、复制字节，并生成 `(key, packed_offset_length)` 元信息。

初始桶数按 `floor(record_count / load_factor + 1)` 计算，默认负载因子为 0.8。空表至少分配一个桶。负载因子越高，空闲槽位越少，构建阶段处理冲突的压力也越大；配置项保留给具体数据分布和空间预算选择。

### 三种插入路径

**主桶为空。** 直接写入节点，链偏移设为零。

**主桶属于同一条冲突链。** 先遍历链检查重复 Key；然后寻找同时能连接主桶与其原后继的空位，将新节点插在主桶之后，并修复相对链。

**主桶被另一条链的节点占用。** 设新 Key 的主桶为 `h`，而当前节点真正属于主桶 `p`。构建器从 `p` 找到该节点的前驱，把被占节点搬到附近可达的空位，修复前驱和后继，再把新 Key 放到 `h`。

例如，A 和 B 都属于桶 3，B 暂存于桶 2；随后一个属于桶 2 的 C 到来。构建器先把 B 迁走、让 A 的链仍能到达 B，然后把 C 放回桶 2。主桶归属与冲突链由此保持清楚，查询不承担迁移工作。

### 邻域搜索与重建

候选位置按距离在两侧查找，当前实现尝试每侧 1–511 的距离，并检查候选与两个链端点的偏移均能编码。搜索过程中预取后续候选节点。

如果邻域耗尽，当前索引构建失败并释放该次数组。构建器在预算允许时将容量翻倍、切换确定性哈希种子后重试，最多额外三次。更大的表和不同的映射有助于分散集中碰撞；预算和重试次数使失败行为可预测。重复 Key 始终报错，避免构建结果依赖隐含的覆盖顺序。

统计项包括直接插入、同链插入、迁移插入和构建次数，记录成功构建的路径分布。

## 4. 批量查询执行

所有执行器共享同一个不可变索引，返回语义一致。选择策略只改变访问顺序。

### Scalar

计算主桶，检查是否为空或命中；若未命中且存在链偏移，就进入下一节点，直到命中或链结束。完成后继续下一个 Key。

这个路径的状态最少，所以作为默认策略。一次查找的工作量取决于实际访问的链节点数；批量查询的开销还包含结果数组与视图构造。

### 前瞻预取

开始时预取窗口内 Key 的主桶；处理第 `i` 个 Key 前，预取 `i + window` 对应的桶，然后执行普通查找。地址范围检查保证最后一批尾部输入安全处理。

该方法利用已知输入提早准备主桶，增加了提前访存的机会，同时会额外计算桶位置。窗口决定提前距离，过近可能来不及准备，过远则可能增加无效缓存占用，因此通过基准选择。

### AMAC

每个状态保存三项：输入位置、当前桶、是否仍然活跃。

1. 初始填充至 `min(window, batch_size)` 个状态，计算并预取各自的主桶。
2. 轮流检查状态。命中就生成视图；空槽或链尾就完成缺失结果；存在下一节点就更新桶并预取，随后处理其他状态。
3. 一个状态完成后，立即接入尚未处理的下一个 Key。
4. 输入耗尽后，继续按相同顺序轮流推进剩余状态，直到全部完成。

同一条冲突链的后续地址依赖当前节点，多条查询之间则相互独立。交错执行用额外的状态检查换取访存重叠机会。当前实现使用单个调用线程；窗口为 1–256，非二次幂窗口同样通过普通循环调度。

状态记录输入位置，因此重复 Key 不会被合并，完成顺序也不会改变输出顺序。`query()` 中的固定大小状态数组只读取已初始化的有效窗口。

## 5. 结果所有权与并发

`BatchResult` 保存 `vector<optional<string_view>>` 与 `shared_ptr<const Snapshot>`。

| 情况 | 结果 |
|---|---|
| Key 存在且非空 | 指向 Value 区域的视图 |
| Key 存在但为空 | 有值、长度为零的视图 |
| Key 不存在 | `nullopt` |
| 同一 Key 重复出现 | 每个输入位置分别得到结果 |

视图避免复制整段 Value，而结果持有快照保证这些地址的有效期。复制一份 `string_view` 本身不会延长生命周期；应用需要保留结果、保留快照，或复制所需内容。

共享指针为接口提供了直接的生命周期模型，也带来引用计数与快照整体保留的成本。一次查询持有一个快照句柄，而不是为每个 Key 单独持有。结果越晚释放，对应快照就存活得越久。

查询、统计读取和保存仅访问快照中的不可变数据。每次查询独立维护状态与输出，可并发调用。对同一个 `BatchResult` 的可变访问遵循普通 C++ 对象的线程同步要求。

## 6. 持久化与加载

### 文件格式

文件使用小端整数，文件头共 40 字节。

| 偏移 | 字节数 | 内容 |
|---|---:|---|
| 0 | 8 | `KWV001\r\n` 魔数 |
| 8 | 8 | 格式版本，当前为 1 |
| 16 | 8 | 记录数 |
| 24 | 8 | Payload 总字节数 |
| 32 | 8 | FNV-1a-64 校验和 |

Payload 按记录重复保存 `uint64 key + uint64 value_length + value_bytes`。校验覆盖文件头前 32 字节和全部 Payload。记录输出顺序按物理索引排列，加载后重新构建索引。

保存记录使文件格式独立于节点指针、结构体填充和当前桶布局，也让加载器能逐条检查长度。启动代价包含记录解析、Value 复制和索引重建。校验和用于检测意外文件损坏；数据来源的认证由应用层处理。

### 保存与发布

保存流程依次执行：检查目标、独占创建临时同级文件、写入文件头与记录、`fsync` 文件、使用 `link()` 发布目标路径，最后清理临时名字。

使用硬链接可保证竞争写入时已有目标不被替换。临时文件与目标同属一个文件系统，目标一旦出现就指向完整文件。实现同步了文件内容；父目录同步和断电后的目录项持久性属于部署时需要单独安排的部分。文件发布依赖 POSIX 硬链接语义。

### 校验加载

加载器打开一次文件并读取该描述符，随后检查文件大小、魔数、版本、记录数、Payload 长度以及每条记录的剩余空间和 Value 预算。解析完成后检查尾部数据与校验和，再进入统一构建路径。

只有完整成功的结果才返回新 `Snapshot`。调用方原来持有的快照不受失败加载影响。应用应将已发布文件作为不可变输入，使用新路径发布下一版。

## 7. 资源预算与异常

| 配置 | 默认值 |
|---|---:|
| 目标负载因子 | 0.8 |
| 最大记录数 | 10,000,000 |
| 最大 Value 区域 | 512 MiB |
| 最大索引节点区域 | 512 MiB |
| 加载文件上限 | 512 MiB |
| 查询窗口 | 32，策略默认为 Scalar |

记录数还受 32 位桶索引范围约束，Value 长度受 32 位扩展长度和 36 位位置范围约束。预算分别限制组件；构建或加载时，原始记录、临时元信息和最终字节区域可能同时存在，所以峰值内存高于最终索引大小。

参数错误和重复 Key 使用 `invalid_argument`，数量、长度或预算错误使用 `length_error`；文件格式和读取失败使用运行时异常，POSIX 操作错误保留系统错误码。调用方可统一捕获 `std::exception`，在服务层记录或转换为业务错误。分配失败保留标准分配异常。
